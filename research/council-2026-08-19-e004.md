## Verified pre-smoke blockers

1. **The held-out set varied across Python processes.** The first draft
   converted configured pairs to a set and then back to a tuple before choosing
   which pair to insert. Python string-hash randomization changed that order,
   while setting `PYTHONHASHSEED` inside the running interpreter could not fix
   it. Codex reproduced different prompts for the same evaluation seed under
   two startup hash seeds.
2. **Depth and held-out pair were locked together.** Both used `len(rows)`
   modulo four, so each reported depth primarily measured one pair rather than
   crossing the factors.
3. **Controlled train and evaluation positions differed.** Training sampled
   arbitrary 64-token windows from a packed controlled stream, frequently
   truncating records and placing their beginning at arbitrary learned absolute
   positions. Evaluation always began a complete record at position zero.
4. **The one-shot budget had no capability derivation.** The original 400-step
   teacher and 300-step student exposed only a small fraction of the roughly
   496k-token controlled stream. A gate failure would have spent the sole
   amendment on a predictable budget guess rather than mechanism evidence.
5. **The fixed design did not yet identify all choices needed for a fair
   implementation.** It lacked an explicit layer map, a common per-layer loss
   contract, fixed seeds and sampling counts, a principled auxiliary scale, a
   learned-versus-untrained teacher control, a student corridor on the primary
   endpoint, and a cost-anchored longer-KD baseline.

Codex independently added a sixth blocker: all first-draft controlled
operations were translations on a modulo-10 ring, so they commuted. Withholding
`left -> right` order tested surface recombination but not an order-sensitive
composition.

## Repairs made before training

- Preserve the configuration's pair order; remove runtime hash-order
  dependence.
- Cross every held-out pair with every depth equally and require exactly one
  held-out pair per evaluation example.
- Start controlled rows on a record boundary, pack only complete records, and
  mask trailing padding from loss. Track complete-record and supervised-token
  exposures separately.
- Replace commuting translations with six affine operations modulo 11.
  Held-out add/multiply orders are algebraically different.
- Replace the guessed one-shot budget with a capability-only ladder at 400,
  2,400, 7,200, and 21,600 steps. Teacher and labels-only student stop at their
  first passing rung; no KD or geometry effect is viewed.
- Gate natural NLL against the frozen training-unigram baseline, evaluate in
  float32, enable deterministic PyTorch algorithms, report held-out accuracy by
  pair, and add a student held-out floor/ceiling corridor.
- Require the later fixed protocol to include teacher-logit geometry and a
  frozen untrained-teacher geometry condition, use the same four student layers
  for every geometry target, exclude the final teacher block from hidden
  matching, calibrate auxiliary weights by one shared pre-step gradient-ratio
  rule, and derive the ordinary longer-KD multiplier from a pre-result cost
  measurement.

## Qualified reviewer claims

The audit's exact controlled-token count was a hand derivation and differed
slightly from the generated artifact; the executable count is authoritative.
Its optimizer-state memory calculation was useful for showing that model
parameters alone fit easily, but it omitted activations, allocator overhead,
and kernel workspaces, so it is not a peak-memory result. The claim that target
geometry necessarily has a damaging irreducible gradient is a plausible
countermechanism, not an established fact; the shared gradient-ratio rule tests
around it without assuming it is true.

## Status boundary

This audit establishes no training result. It only improves prospective
validity. E004 remains at the smoke/capability stage until a clean commit freezes
the repaired configuration and the ladder runs once. A passing ladder licenses
implementation and registration of the paired fixed comparison; it does not
support activation-specific distillation, compression, or efficiency by
itself.
